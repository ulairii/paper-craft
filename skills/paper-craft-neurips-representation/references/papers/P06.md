## Writing move: Build the argument around what should remain invariant

InfoMin asks a question that connects intuition, theory, and practice: which differences should a representation ignore? The answer depends on the downstream task. A controlled digit-and-background example makes this dependence concrete before learned views and practical augmentation show how to use the principle.

## Experimental logic

The toy tasks vary which factors two views share. Real-image studies vary crop distance, color, and augmentation strength. The supplementary frequency-separation experiment is especially revealing: reducing the information proxy along different paths can produce different downstream outcomes. The important variable is what information remains, not only how much.

## Detail placement

Explain the preserved task information before introducing minimal sufficient encoders. Keep those assumptions with the proposition. Distinguish the learned semi-supervised view generator from the manually designed ImageNet augmentation recipe. Detailed proofs and augmentation grids can follow the main explanatory thread.

## Interpretation

The measured InfoNCE quantity is an architecture-dependent proxy, and minimizing it alone can remove useful signal. Labels used to learn views remain part of the pipeline even when subsequent representation training is unsupervised. The strongest practical claim concerns task-appropriate invariance, not arbitrary augmentation strength.
