Peng Chen; Hao Chen. **IEEE S&P 2018**. [Paper record](https://www.ieee-security.org/TC/SP2018/program-papers.html#oakland-18-495) · [Official venue listing](https://www.ieee-security.org/TC/SP2018/program-papers.html) · [Full text](https://web.cs.ucdavis.edu/~hchen/paper/chen2018angora.pdf).

## Writing move: Organize several techniques around the decisions in one search

Angora makes its components answer successive questions: which bytes matter, how to change them, what units to change together, and when the input needs to grow. The running program gives these questions concrete meaning. Taint analysis and numerical search become parts of one explanation rather than a list of independent optimizations.

## Experimental logic

The gradient, random, and magic-value searches use the same fixed input pool, making their differences interpretable. The length experiment measures attempts and useful inputs, including cases where length changes have little value. Throughput is reported separately from discovery: better-directed search can find more while executing fewer inputs per second.

## Detail placement

Keep the concrete branch objective, byte grouping, and amortization of taint analysis beside the method. Explain that calling-context feedback is approximate. Detailed taint-tree storage can follow the central search description. State which baseline results were imported for LAVA-M and which tools were actually compared on the real programs.

## Interpretation

Numerical search over a discrete program is a heuristic, not a complete constraint solver. Real-program crash classes were deduplicated with afl-cmin; the count is not automatically a count of independently confirmed vulnerabilities. The useful claim is improved search under stated conditions, not removal of all analysis overhead.
