# P08: Pangolin: Incremental Hybrid Fuzzing with Polyhedral Path Abstraction

Heqing Huang; Peisen Yao; Rongxin Wu; Qingkai Shi; Charles Zhang. **IEEE S&P 2020**. [Paper record](https://5hadowblad3.github.io/files/SP2020.pdf) · [Official venue listing](https://www.ieee-security.org/TC/SP2020/program-papers.html) · [Full text](https://5hadowblad3.github.io/files/SP2020.pdf).

Source locations: Sections I–VII; nested-branch example, Figures 2–12, Tables III–VII.

## Writing move: Let one intermediate object explain two improvements

Pangolin identifies work lost between hybrid-testing stages: one satisfying input does not preserve the region from which it came. A cached path approximation then supports both constrained mutation and later solving. The nested-branch example makes both uses concrete before the geometric representation is formalized.

## Experimental logic

The solver-reuse comparison measures one use of the abstraction, while fixed-time sampling on exported constraints measures the other. Coverage curves expose a warm-up cost followed by reuse benefits. The incomplete-patch case returns to the central distinction: reaching a branch is insufficient if subsequent inputs do not explore values that trigger the fault.

## Detail placement

Keep the direction of approximation explicit. An over-approximation can contain infeasible inputs; an unsatisfiable abstraction safely prunes, whereas a satisfiable one still requires the original condition. Explain preprocessing and resource budgets beside the comparisons. Full sampling machinery and bug inventories need not interrupt the cached-object story.

## Interpretation

The 24-hour LAVA-M results include unlisted injected bugs. Real-program reporting includes entries whose status is pending, so avoid converting the collection into uniformly confirmed vulnerabilities. Neither the use of a polynomial-time sampling procedure nor the sound approximation makes whole-program bug discovery complete or polynomial-time.
