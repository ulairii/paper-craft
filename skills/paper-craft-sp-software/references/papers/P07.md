# P07: IJON: Exploring Deep State Spaces via Fuzzing

Cornelius Aschermann; Sergej Schumilo; Ali Abbasi; Thorsten Holz. **IEEE S&P 2020**. [Paper record](https://nyx-fuzz.com/papers/ijon.pdf) · [Official venue listing](https://www.ieee-security.org/TC/SP2020/program-papers.html) · [Full text](https://nyx-fuzz.com/papers/ijon.pdf).

Source locations: Sections I–VIII; maze, Mario, protocol and hash-map cases; appendix CGC analysis.

## Writing move: Make a small abstraction the bridge between human insight and search

IJON distinguishes known state values, known state changes, and missing intermediate progress signals. Each gets a concrete example before the annotation interface. A maze needs positions, a protocol needs message sequences, and a hash lookup needs a more informative comparison signal. The abstraction—not annotation syntax—is the explanatory center.

## Experimental logic

Baseline-versus-annotated comparisons show what added feedback changes. TPM experiments retain the same individually observed commands while reaching more combinations, directly testing the state argument. Games make the mechanism visible; parser and gadget examples connect it to security. Multiple fuzzers demonstrate that the feedback can complement different search engines.

## Detail placement

Keep analyst participation and the meaning of each exposed state explicit. The Mario experiment modifies the game, and CGC cases sometimes require more than one annotation or preprocessing step. One-line code changes do not measure total analyst effort. Full helper APIs and individual challenge accounts can be placed after the main examples.

## Interpretation

The study uses one expert for the CGC analysis and reports approximate effort. It does not establish novice usability or full automation. The useful transferable claim is that a compact, informed feedback signal can make search productive where coverage has little to say. Preserve that idea without claiming every deep state problem is solved.
