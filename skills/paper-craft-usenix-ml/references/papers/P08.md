# P08: Poison Forensics: Traceback of Data Poisoning Attacks in Neural Networks

Shawn Shan; Arjun Nitin Bhagoji; Haitao Zheng; Ben Y. Zhao. **USENIX Security 2022**. [Official paper](https://www.usenix.org/conference/usenixsecurity22/presentation/shan) · [Full text](https://www.usenix.org/system/files/sec22-shan.pdf).

Source locations: Sections 1–10; traceback definition, iterative pruning, Tables 2–11; Appendix A.

## Writing move: Create a new problem by changing when the system is used

Poison Forensics moves from preventing poisoning to investigating a known misclassification after an attack. That change supplies a concrete input and a different output: training records associated with the incident. Because poisoning operates through groups of examples, the method removes groups judged innocent rather than attempting exact attribution to every point. A binary decision replaces a harder ranking problem.

## Experimental logic

Precision and recall measure recovery of poisoned records. Differences between dirty-label and clean-label attacks lead to an explanation involving weaker separation and more pruning iterations. Removing missed physical-poison samples and comparing with removal of an equally sized random subset gives the explanation additional evidence. Countermeasures report attack success alongside traceback quality.

## Detail placement

Keep access to the original data, model, pipeline, and observed incident in the main text. Describe functional unlearning as the approximation used for the pruning decision. The theory and full attack settings can follow the main algorithm. State that connecting recovered records to a responsible source additionally requires reliable provenance.

## Interpretation

The experiments start from successful poisoning incidents; exploratory recognition of non-poison events is a separate result. Record recovery does not prove an attacker’s identity or establish a globally minimal causal set. The reported 1,000 events per task reuse ten attack versions. These details preserve the paper’s useful incident-response claim without expanding it into automatic attribution.
