# P03: FIRM-AFL: High-Throughput Greybox Fuzzing of IoT Firmware via Augmented Process Emulation

Yaowen Zheng; Ali Davanian; Heng Yin; Chengyu Song; Hongsong Zhu; Limin Sun. **USENIX Security 2019**. [Official paper](https://www.usenix.org/conference/usenixsecurity19/presentation/zheng) · [Full text](https://www.usenix.org/system/files/sec19-zheng_0.pdf).

Source locations: Sections 1–6; emulation design, transparency checks, throughput and firmware evaluations.

## Writing move: Organize a systems contribution around competing practical requirements

FIRM-AFL frames firmware fuzzing as a compatibility–throughput problem. Full-system emulation supplies an environment but is expensive; process emulation is faster but lacks system context. Augmented process emulation combines these roles. The introduction’s bottlenecks map to the system design, giving each mechanism a purpose beyond a list of implementation features.

## Experimental logic

Transparency checks, throughput measurements, and vulnerability experiments establish different parts of the argument. A strengthened full-system baseline makes the speed comparison more informative. The dnsmasq case explains a slowdown through frequent system interactions and then shows the effect of handling suitable calls locally. This is a useful pattern for turning an exception into a mechanism explanation.

## Detail placement

Keep bootability, POSIX assumptions, supported architectures, snapshots, and system-call handling in the main account. Explain which firmware images pass the applicability filters. Full firmware manifests and emulator settings can move to supporting material. Successful normal-request traces and known exploits are concrete compatibility evidence, not a formal equivalence proof.

## Interpretation

The reported speedup depends on which snapshot baseline is used. Faster execution does not imply proportionally more bugs, and a timeout is not a measured discovery time. The system targets firmware that its underlying environment can boot; architecture coverage in a dataset does not mean compatibility with every IoT device.
