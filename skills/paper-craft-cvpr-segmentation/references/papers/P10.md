## Writing move: Turn an ambiguous field goal into a concrete deliverable

OneFormer separates a shared architecture from a shared trained model. Figure 1 compares the number of architectures, models, and datasets, making the remaining unification problem explicit. A task token tells the model which grouping to produce, while task-conditioned training and contrastive supervision support that distinction.

## Experimental logic

Task-token and joint-training comparisons address the train-once goal. Changing the task token at inference produces expected changes in secondary metrics: instance mode drops stuff predictions, while semantic mode merges instances. These decreases are useful evidence of task-dependent behavior rather than failures to hide.

## Detail placement

The text-list example shows how the same scene yields different mask counts and targets for each task. Keep the task input separate from ground-truth-derived training text, whose mapper is removed at inference. Most routine implementation settings are placed in the appendix, preserving space for the new training formulation.

## Interpretation

The supplement examines annotation discrepancies that affect COCO instance comparisons. Name the evaluated annotation set where it changes the meaning of a result. Train once means across tasks for the chosen dataset, not one global set of weights covering all datasets. Prefer this concrete scope to dismissing prior work as not truly universal.
