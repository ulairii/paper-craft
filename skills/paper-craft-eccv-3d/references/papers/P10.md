## Writing move: Let invariant and equivariant features perform different jobs

PARE-Net resolves an apparent tension: matching needs descriptors that remain comparable under rotation, whereas pose estimation needs features that retain how orientation changes. Explaining these two jobs makes the shared representation and feature-based pose hypotheses a coherent contribution.

## Experimental logic

Fixing correspondences while changing the estimator isolates the pose-estimation benefit. Backbone comparisons test the feature operator; crop controls show that overlap augmentation also contributes. Rotated tests address the motivation, while transfer experiments reveal that a strong local representation does not automatically make the entire coarse-to-fine pipeline generalize.

## Detail placement

A single correspondence supplies multiple oriented feature vectors, not just two point coordinates; that distinction is essential to the pose claim. Define registration and transformation recall where they are used. State when rotation and translation errors average only successful pairs.

## Interpretation

The high cross-domain result from fine matching plus RANSAC should not be attributed to the full pipeline, whose transfer is weaker. Equivariance of an operator does not guarantee identical behavior for every preprocessing and matching stage. These boundaries explain which part of the approach travels well.

## Original writing illustration

Before: One matched point uniquely determines any rigid transformation and solves domain shift.

After: Each matched point carries oriented feature vectors that support a pose hypothesis; consensus across correspondences then selects and refines the transformation.
