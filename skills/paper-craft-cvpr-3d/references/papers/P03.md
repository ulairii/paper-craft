## Writing move: Sell a useful operating point honestly

PointPillars frames a practical choice between fast fixed encodings and more costly learned representations. Learning vertical pillar features allows the main computation to use 2D convolutions. This explains both the accuracy goal and where the speed comes from in one sentence.

## Experimental logic

The resolution study maps the speed–accuracy tradeoff, and the encoder comparison uses a common backbone to isolate the representation. Table 5 acknowledges that a VoxelNet-style encoder can be more accurate. The runtime discussion connects spare throughput to larger scenes and constrained hardware instead of treating FPS as self-explanatory.

## Detail placement

Keep the pillar representation and the removal of vertical convolution clear. Height remains available in point features; a 2D feature map does not imply that all height information is discarded. Place the runtime breakdown near the efficiency claim, with the relevant implementation setting.

## Interpretation

An operating-point contribution remains strong without winning every accuracy comparison. The paper offers plausible reasons for reimplementation differences rather than presenting them as established causes. Small categories can respond differently to coarser grids than cars do.
